# UI 设计哲学（跨平台共享）

> 本文件是 `frontend-design`（Web）与 `app-design`（App）共享的**跨端规范**，覆盖四层：
> ① 法规层（WCAG 2.2 AA）· ② 平台层（Apple HIG / Material 3）· ③ 系统层（Token/色彩/字体/图标/贴图/交互）· ④ 哲学层（设计立场、原则、工作法、输出纪律）。
> 两 skill 各自负责平台**实现层**（CSS/Compose/SwiftUI 具体写法），本文件负责共享的设计决策与判定阈值。
> 变更本文件时须同步评估对两个 skill 的影响。

## 四层模型

| 层 | 内容 | 约束力 |
|---|---|---|
| ① 法规层 | WCAG 2.2 AA | **不可违反**，违反即缺陷 |
| ② 平台层 | Apple HIG（Liquid Glass）/ Material 3（Expressive） | 不可违反 |
| ③ 系统层 | Token / 色彩 / 字体 / 图标 / 贴图 / 交互 | 不可违反 |
| ④ 哲学层 | 设计立场 / 设计原则 / 两遍工作法 | 追求差异化 |

> ③ 管**一致性**，④ 管**差异性**，二者不冲突，不得互相否定。

## 设计立场
- 以小工作室主理人视角工作：每单必须有不可误认的视觉身份，拒绝模板提案。
- 每次只做一个可辩护的美学冒险，说清为什么是它；其余保持安静克制。
- 简约靠间距/字型/细节精度取胜，极繁靠精密执行取胜，不半吊子。

## 锚定主题（先定再画）
- 若 Brief 未锁定主题，自己先定：一个具体主题 + 受众 + 界面唯一任务（页面/屏幕），并显式说出选择。
- 从主题自有世界取材：材料、器具、质感、行话、器物/数据形态，用真实内容填充，不用 Lorem。
- 若环境提供记忆/过往会话工具则复用用户偏好与过往设计，否则跳过；避免重复自己。

## 设计原则
- **Hero 即论点**：首屏放主题世界里最具特征的东西：标题、图、动画、live demo、交互瞬间，二选一讲清理由。`大数字+小标签+渐变点缀`是模板答案，非最优不用。
- **字体即个性**：Display + Body 刻意搭配，不用万能默认款；必要时加 Utility（注释/数据）。定字阶、字重、宽度、间距，让字型本身可被记住。
- **结构即信息**：眉题、编号、分割线、标签必须编码真实信息。`01/02/03` 仅当内容真是序列（流程/时间线，顺序承载信息）才用，否则不用。
- **动效克制**：只在服务主题处用：首屏序列、滚动显现、hover/tap 微交互、环境氛围。宁要一个编排好的瞬间，不要满屏散点。无益动效即 AI 味。
- **文案即材料**：用户侧命名，不暴露系统实现；主动语态，按钮名即动作（`保存修改`不叫`提交`），全流程统一；失败/空态给方向不抒情，不道歉不含糊；口语句式大小写，无填充词，每个元素只做一件事。
- **落地判断**：以上原则在 Web 与 App 同样成立；平台差异只体现在签名元素的实现手段（CSS/转场/触觉）与底线条目，自检以本清单 + 各平台实现层合并判定。

## 三层 Token 架构

```
① Primitive 原始层  纯数值，不表达用途，永不修改
   color/blue-500 · space/8 · radius/12 · duration/250
② Semantic  语义层  按角色命名，改主题只改这一层映射
   color/surface/default · color/text/primary · color/border/subtle
③ Component 组件层  只消费语义 token，禁止硬编码
   button/bg/primary · input/border/focus
```

- 命名：`category/role/modifier`（如 `color/feedback/error`、`typography/heading/xl`）。
- 布局 token 用 `layout/` 前缀，全产品各只有一个值：`layout/gutter`（左右留白）、`layout/container-max`（内容最大宽）；同产品出现第二个值即缺陷（见 §布局与对齐）。
- **硬禁令**：③ 组件层出现任何字面色值/像素值即视为缺陷。
- Token 输出分两层：**全局层**（一次确定，全产品复用）+ **产品层**（本次交付可覆盖，须说明覆盖了什么、为什么）。

## 色彩规范

### 构建：OKLCH
`oklch(L C H)` 三维度正交，解决跨色相明度不一致（手调 Hex 常见翻车点）。

| 变量 | 作用 | 建议区间 |
|---|---|---|
| `L` 明度 | 层次 | 正文 0.55-0.70 / 亮背景 0.95-1.0 / 暗背景 0.12-0.18 |
| `C` 彩度 | 素净↔浓烈 | 辅助 ≤0.05 / 主色 0.10-0.18 |
| `H` 色相 | 自由旋转 | 同产品色相差 ≤30° |

**构建规则**：定 1 个 `L` + 1 个 `C` 跑满色相环 → 得到一组天然和谐的颜色。

### 语义映射表（暗色为**重映射**，不是反转）

| 语义 token | 亮色 | 暗色 | 规则 |
|---|---|---|---|
| `surface/default` | `#FAFAF9` | `#0F0F11` | 暗色**禁纯黑** |
| `surface/raised` | `#FFFFFF` | `#1A1A1D` | 暗色靠**提亮**表达层级 |
| `surface/sunken` | `#F4F4F5` | `#08080A` | 低于默认层，凹陷元素 |
| `border/default` | `#E4E4E7` | `#2A2A2E` | 暗色需比预期更亮 |
| `text/primary` | `#18181B` | `#FAFAFA` | |
| `text/secondary` | `#52525B` | `#A1A1AA` | |
| `text/disabled` | `#A1A1AA` | `#52525B` | |
| `accent/base` | `{主色}` | `{H+10°, L+0.12, C×0.85}` | 暗色**提亮、降彩** |
| `feedback/error` | `#DC2626` | `#F87171` | 同上原则 |
| `feedback/success` | `#16A34A` | `#4ADE80` | |
| `feedback/warning` | `#D97706` | `#FBBF24` | |
| `feedback/info` | `#2563EB` | `#60A5FA` | |

### 对比度（WCAG 2.2，不可违反）

| 场景 | 最低比 |
|---|---|
| 正文 | **4.5:1** |
| 大字（≥24px / ≥18.66px Bold） | **3:1** |
| UI 组件边界、图标、图表 | **3:1** |
| 焦点指示器 | **3:1**（对比相邻色） |

> 暗色下用**半透明前景色**（如 `rgba(255,255,255,.62)`）跨背景比固定色值更稳。

## 字体规范

### Web（rem，基准 16）

| 角色 | 字号 | 字重 | 字距 | 行高 |
|---|---|---|---|---|
| Display | `clamp(2.25rem, 5vw, 4rem)` | 700 | -0.02em | 1.05 |
| H1 | 2.25rem | 650 | -0.015em | 1.2 |
| H2 | 1.75rem | 650 | -0.01em | 1.25 |
| H3 | 1.375rem | 600 | 0 | 1.3 |
| Body | 1rem | 400 | 0 | 1.6 |
| Body-S | 0.875rem | 400 | 0 | 1.5 |
| Caption | 0.75rem | 500 | 0.01em | 1.4 |

### App（必须尊重系统字体缩放）
- **iOS 正文 17pt**（不是 16，最常见错误）；支持 Dynamic Type；**禁止用 `fixedSize` 锁死字号**。
- **Android 单位必须用 `sp`**（不是 `dp`）；支持 Font Scale；正文基准 16sp / 行高 24。
- 移动端**不使用** `clamp()` 视口缩放，字号跟随系统。

### 字体加载
- Web：Display 用 webfont，`<link rel="preconnect">` + `font-display: swap`。
- App：**仅用系统字体**（SF / Roboto），不自托管字体文件（除非主题需要）。

## 间距 · 圆角 · 高度

**间距**（4/8 基准）：`0 · 2 · 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80 · 96 · 128`
Web 用 `px`；iOS 用 `pt`；Android 用 `dp`。

**圆角**：`0 · 2 · 4 · 8 · 12 · 16 · 20 · 24 · full`
圆角同心：内层圆角**不得大于** 外层圆角 − 内边距（理想值即此，落最近下档 token）；同值圆角嵌套判错。

**高度（Elevation）**：
- Web：`0/1/2/3/4/5` 六级 `box-shadow`，各级同时改 `Y` 与 `blur`。
- Android M3：`tonalElevation`（改**表面色**）与 `shadowElevation`（改**投影**）**分离**，M3 方向是 tonal。
- iOS：仅 3-4 级；避免大面积强投影，用分隔线 + 明度差。

## 布局与对齐（跨端）

**与相邻章的分工**：本章定「怎么摆」；颜色与字号归 §色彩规范、§字体规范，宽度分流归 §自适应布局，控件内部结构归 §组件基线。

- **组装只允许五种原语**：Stack（纵向节奏）/ Cluster（横向可换行）/ Grid（二维）/ Sidebar（主 + 辅）/ Cover（满屏）。区间距由原语统一给出，**禁止逐块写 margin**。
- **对齐不变量**（违反即缺陷）：
  1. 同容器内只允许一个对齐轴（leading / center / trailing），同层元素共轴；需要混轴时靠容器分级，不靠逐块偏移。
  2. 块级元素左右边界对齐容器 gutter，**不接受「差 2–6px」的逐块微调**。
  3. 不同字号并排（标题 + 副标题）按**文本基线**对齐，不按盒子中心对齐。
  4. 数字、金额、表格数值列右对齐并启用 `tabular-nums`。
- **容器只允许两个值**：`layout/container-max`（内容最大宽）与 `layout/gutter`（左右留白），二者进 Token；同产品出现第二个值即缺陷。
- **垂直节奏**：块内（intra）与块间（inter）间距至少差 2 档；全页间距等值会让层级塌陷。
- **列宽由网格模板定义**，不用内容撑开；否则换语言、换数据即错位。
- **光学对齐**：图标 + 文字用固定图标盒并按文本 leading 对齐，不靠 flex 居中「看起来差不多」。

**天花板**：跨字号基线的亚像素差异、衬线字体的光学边距需截图裁定；本节只给判据。

## 组件基线（跨端）

**与相邻章的分工**：本章只定控件契约与状态；取值（颜色 / 字号 / 圆角 / 阴影）归 §色彩规范、§字体规范、§间距 · 圆角 · 高度。

- **一类控件全局只定义一次**（Web 组件类 / App 主题组件），页面只做「组合 + 选变体」，不得就地改样式。
- **契约表最小集**，每行必须给：`control-size`、水平内边距、字号角色、圆角角色、状态集 —— Button / Input / Select / Card / ListRow / Tab / Badge / Dialog。
- **`control-size`**：Web 32 / 40 / 48（32 仅桌面指针场景，如表格行内操作）；App 44 / 48 / 56（pt / dp）。任一可点控件的命中区域 ≥ §触达尺寸 取最严值；视觉尺寸小于命中区时用 padding 补齐，**不缩命中区**。
- **圆角角色**：surface（容器）/ control（控件）/ pill（胶囊）；同心判据仍归 §间距 · 圆角 · 高度。
- **变体白名单**：size（sm / md / lg）× variant（primary / secondary / ghost / danger）。新增变体必须回写契约表，不允许临时第 5 种。
- **状态集按适用取**：default / hover（仅可悬停设备）/ focus-visible / active / disabled / loading / error。数据视图另需 empty、loading、error 三态。
- **同类语义固定写法，不得换**：表单 → 字段组 + 可见标签；选项集 → 分段控件或单选组；危险操作 → 确认对话框；数据为空 → 空态组件 + 下一步动作。
- 长文案换行不截断；同屏只允许一种密度档（comfortable / compact）。
- **反例即缺陷**：同页出现 ≥3 种按钮高度、≥2 种控件圆角、≥2 种输入框边框。

**天花板**：契约表的具体数值需按产品品牌调整（调整即回写本节）；本节只定档位语义与状态集合。

## 跨页一致性（跨端）

**与相邻章的分工**：本章只定跨页不变量；页内结构与栅格归 §布局与对齐，转场与返回归 §导航与转场。

- **Page Shell 槽位固定**：Web 为 `header / main / footer`，App 为 `topBar / content / bottomBar|rail`。每个槽位的高度、内边距、粘性、层级、最大宽度各只有一个值，进 Token。
- **跨页不变量**（跨页同位、同尺寸、同顺序）：品牌标识、主导航、页脚、主 CTA、帮助入口。顺序一致性对应已登记条款 `3.2.6`。
- **导航当前态**：Web 用 `aria-current="page"`，App 用选中态；同位置同视觉，不因页面不同换样式。
- **多页交付先出「页面清单 × 骨架继承」表**再写码；detail、modal、空态等碎片页必须声明继承哪个 shell。
- **交付抽 2 页比对五项实测值**：header 高、gutter、卡片圆角、按钮高、字号角色。不一致就改到一致，不解释。

**天花板**：跨页一致性只能抽页核对，无法穷举；抽页数按交付规模（≥2 页，多页产物建议 3 页）由执行者定。

## 导航与转场（跨端）

**与相邻章的分工**：转场参数与降级口径在本章；动效必要性判据与滚动降级归 §动效与滚动。

- **先定层级模型再选动效**：push（进入下级）/ modal（阻断当前任务）/ replace（同级切换）/ reveal（原地展开）。
- **选型表**：push = 水平位移 + 淡入；modal = 自下而上；replace = 交叉淡化；tab 切换 = 无位移或交叉淡化。方向必须与层级一致，返回时反向。
- **时长与缓动只复用现网 token**（`motion/fast|base|slow`、`easing/standard|emphasis`），不逐页自定义。
- 共享元素每次最多 1 个，且不得承载唯一信息；无转场时信息仍须完整。
- **返回恢复**：滚动位置、筛选条件、已填输入、选中项；转场期间不因整页重载产生闪烁。
- 深链直达须给父级返回路径，不产生无出口页面。
- **降级**：无转场时页面完整可读可用；系统减弱动效时降为瞬时切换。静态多页产物默认交叉淡化或直切；跨文档 View Transitions 属 limited availability（2026-10 核读），只能作增强，不得作为唯一衔接手段。

**天花板**：转场时长的手感、共享元素在复杂布局下的稳定性需实机观看裁定；本节只给模型与降级口径。

## 图标规范

### 库选择（免费、商用可用；默认推荐，可按项目调整）

| 库 | 授权 | 风格 | 数量 | 默认用于 |
|---|---|---|---|---|
| **Lucide** | ISC | 单一线框 | 1700+ | **Web 默认**（Feather 的活跃分支） |
| **Material Symbols** | Apache 2.0 | 5 风格可变字体 | 3000+ | **Android 默认** |
| **SF Symbols** | Apple | 系统原生 | 7000+（SF Symbols 8 beta，2026-10） | **iOS 默认**（⚠️ 见下） |
| Phosphor | MIT | **6 字重** | 1000+ | 需字重表达状态 |
| Tabler | MIT | 线性 | 2000+ | 数据密集后台 |

**切换触发条件**（任一满足即换库）：
- 默认库缺目标语义图标 → 换 Phosphor/Tabler。
- 品牌需要字重变化表达状态 → Phosphor。
- 需跨端**同一图形** → **禁用 SF Symbols**，全端统一 Lucide/Phosphor。

> ⚠️ **SF Symbols 授权限制**：Apple 授权**仅允许用于 Apple 平台**，**不可用于 Web 或 Android**；符号可导出并用矢量工具编辑生成自定义符号（Apple 官网口径），授权范围仍以 Apple 许可为准。

### 绘制规范
| 项 | 规定 |
|---|---|
| 网格 | 统一 **24×24** 基准网格 |
| 描边 | 24px 时 2px；32px 时 2.5px；40px 时 3px（**随尺寸等比，非固定 2px**） |
| 光学对齐 | 圆形图标留 2px 边距；斜线形图标（如 play 三角）需**手动光学校正** |
| 尺寸序列 | `16 · 20 · 24 · 32 · 40`，同场景只用一档 |
| 端点 | 圆角端点（`stroke-linecap: round`），与圆角 Token 一致 |

### 使用规范
1. **同语义同图标** —— 删除不得在 trash/bin/删除 之间混用，全应用唯一。
2. **图标不独立承载语义** —— 必须配文字标签，或 `aria-label` / `Semantics`。
3. **状态用填充度区分，不换图标** —— 「已收藏」用 filled，图形本身不变。
4. 图标按钮必须带 Tooltip（Web）/ `Semantics`（App）。
5. 色彩跟随语义 token，不写死。
6. **禁止仅用图标表达状态变化**（颜色 + 文字双通道）。

## 贴图规范（AI 生成 + 纯色块矢量混用）

### 角色划分（按角色，不按场景混用）

| 角色 | 来源 | 用途 |
|---|---|---|
| **氛围类** | AI 生成 | hero、空态插画、品牌故事页、引导页 |
| **功能类** | 纯色块矢量 | 图标、功能性插图、数据可视化、状态提示、装饰图形 |

### 三条硬约束
1. **同一屏不混用** —— 一屏内只出现一种来源。
2. **同一角色不混用** —— 空态插画要么全 AI、要么全矢量，不得部分。
3. **全局只有一套色调处理** —— 两种来源都施加统一 duotone（映射到 `accent/base` + `surface/raised`）。

### 通用规格
- 圆角统一 `radius/12`，不逐张自定义。
- 比例限定 4:3 / 1:1 / 16:9 三档，禁止第四种。
- 暗色模式**降亮度 + 轻微去饱和**，**不反转**。

### AI 生成硬约束
- **不得出现文字**（生成模型中文字形必错）→ 界面文字一律真实字体渲染。
- 检查手部/肢体数量、镜像文字。
- 不做精细面部特写。
- 商用**强制**走下方合规检查清单；留痕 manifest **必须**落盘，未落盘不得交付。

### AI 贴图商用合规检查清单

**生成前**：
| 检查项 | 要求 |

| 风格提示词 | **禁止**「模仿 XX 在世艺术家风格」用于商用 |

| 解剖错误 | 手部/肢体数量、镜像文字 |

## 交互规范

### 感知时延阈值

| 时延 | 感知 | 设计义务 |
|---|---|---|
| **< 0.1s** | 即时 | 直接响应，**不显示任何加载指示** |
| **< 1s** | 流畅 | 状态变化可见，不打断 |
| **< 10s** | 注意力游走 | **必须**有进度指示；**禁止裸转圈** |
| **> 10s** | 放弃 | 转后台 + 完成后通知 |

### 状态机（每个数据视图必须有四态）

| 状态 | 规范 |
|---|---|
| **Loading** | 有结构 → **骨架屏**（尺寸与真实内容一致）；可确定进度 → 进度条；禁止裸转圈 |
| **Empty** | **首次空**（教用户如何开始）与**筛选后空**（提示放宽条件）**文案必须不同**；禁止「暂无数据」 |
| **Error** | 说明**原因 + 下一步动作**；**保留用户已输入内容**；提供重试 |
| **Success** | toast / 微动效轻反馈；**不打断主流程** |

### 边界状态

#### 网络异常（三态必须区分）
| 子态 | 判定 | 文案与行为 |
|---|---|---|
| **无网络** | 系统网络状态 = 断开 | 「网络不可用，检查连接后重试」+ 重试按钮 |
| **弱网超时** | 请求超时 | 「连接超时」+ 重试；**不显示为服务端错误** |
| **服务端错误** | HTTP 5xx / 业务错误码 | 说明原因 + 下一步；**保留已输入内容** |

通用规则：有本地缓存 → **优先展示缓存 + 「数据可能不是最新」标记**，不显示空白错误页；网络恢复后**自动重试一次**，不重复弹提示；禁止无信息量的「加载失败」文案。

#### 低电量 / 省电模式
- 检测：iOS `NSProcessInfo.isLowPowerModeEnabled` / Android `PowerManager.isPowerSaveMode()`。
- 触发后：禁用非关键动画，动效时长统一降到 `motion/fast`；降低图片质量、禁用大图预加载。
- **只减装饰，不减功能，不改变信息层级。**

#### 后台恢复
- 时机：iOS `applicationWillEnterForeground` / Android `onResume`（**不得阻塞主线程**）。
- 数据新鲜度阈值 **5 分钟**，超时静默刷新。
- **不重放进入动画**；刷新失败不覆盖已展示内容。

#### 中断恢复
- **长表单**：草稿自动保存本地；恢复时提示「继续上次编辑？」，不静默丢弃。
- **提交/支付类**：**幂等设计**防重复提交；提交中禁用按钮 + 显示进行中态。

#### 空数据 vs 无权限（必须区分）
> **无权限不得显示「暂无数据」** —— 会误导用户以为数据不存在。
| 状态 | 文案方向 |
|---|---|
| 空数据 | 教用户怎么开始 |
| 无权限 | 说明**缺什么权限** + **如何获取**（申请入口 / 联系管理员） |

### 生成式 AI 交互基线（跨端，非 WCAG 专项）

> 依据：Apple HIG · Generative AI（2026-06）。适用于任何「AI 生成 / 改写内容」的界面；模型能力选型与法规细节不在本层。
> **归因**：除标 ★ 两条外均为 HIG 直述（或等价收紧）；★ 为本仓加严（HIG 该节为 Consider 段，内含 Generally 表述）。

- **保留控制**：生成结果可编辑 / 撤销 / 重试 / 关闭；用户修正生效后给明确回执，不静默替换。
- **不可逆先确认**：删除、代付款、对外发送等有代价的操作，AI 只能建议，执行前必须人工确认。★（HIG 同段为 Consider 标题「不可逆/潜在问题先取许可」+ Avoid 句「不自动执行破坏性/难撤销动作」+ Generally 句「显著动作先确认」；本仓升为硬基线并扩到全部有代价动作）
- **来源透明**：明确标识哪些内容由 AI 生成 / 改写，**不得让人误以为是人类产出**；并遵守所在地区的披露要求。披露 AI 参与属对外义务，**不算**违反「文案即材料」的不暴露实现。
- **不把不确定当确定**：可能出错的内容显式提示「可能不准确」；事实性高风险场景（金额 / 医疗为本仓扩例，HIG 举例为日期与人物信息）须人工核验或加显著不确定标注后才呈现；输出受限时给「怎么问得更好」的提示与示例，而不是空白或一句「无法处理」。
- **等待要具体**：用「正在为食材找替代」这类进行中描述替代「处理中…」；>10s 转后台（阈值见 §感知时延阈值，不重述）。
- **不确定就多版本**：意图模糊时给 2–3 个差异明显的结果供选，不赌一个「最佳答案」。★（HIG 为 Consider 级且允许单结果；本仓按硬基线要求）
- **隐私**：端侧优先；走服务器时先告知「会发送什么」并获授权，只传最小必要数据，并提供退出方式。

### 动效与滚动

> Token **全局唯一一组**；平台动效曲线跟随系统（iOS spring / M3 spring），**自有 token 只管时长与编排**。

| Token | 值 | 用途 |
|---|---|---|
| `motion/fast` | 150ms | hover / press / 微交互 |
| `motion/base` | 250ms | 元素进出 |
| `motion/slow` | 400ms | 页面转场 |
| `easing/standard` | `cubic-bezier(0.2, 0, 0, 1)` | 进入 |
| `easing/emphasis` | `cubic-bezier(0.05, 0.7, 0.1, 1)` | 强调 / 退出 |

- **动效有因**：每个动画必须能说出服务主题的理由；系统减弱动效设置下仍可用（三平台 API 见 §通用自检清单，SC 2.3.3 见 §无障碍基线，均不在此复述）；**降级只减装饰不减功能**（与 §交互规范 · 边界状态的低电量口径一致），且**动效不得阻塞输入与首屏可读**。
- **滚动驱动只做渐进增强**：`animation-timeline` / `view()` 属 Limited availability（非 Baseline，2026-10-26 核 MDN），**不得**作为默认可读态的前提——必须 `@supports` 包裹、无动画时内容完整可读、长列表禁用、不得替代加载态。

### 触达尺寸（取最严者）
Apple HIG **44×44 pt** / Material Design 3 **7–10 mm** / WCAG 2.2 AA **24×24 CSS px**（或间距足够防误触）。

### 表单与校验（跨端）

> 依据：WCAG 2.2 `3.3.1` / `3.3.2` / `3.3.3` / `3.3.4`（2026-10-27 直读 Quick Reference，等级 A/A/AA/AA）；交互时机引 Apple HIG「Text fields」2026-10-27 直读（`developer.apple.com/design/human-interface-guidelines/text-fields.md`）：「Validate fields when it makes sense… when entering an email address, it's best to validate when people switch to another field; when creating a user name or password, validation needs to happen before people switch to another field」。

- **校验时机**（★ 本仓判断，WCAG 3.3.2 只要求标签/说明不规定时机）：首次提交前**不实时报错**；首次提交后字段失焦即校验；提交失败后**整表**再校验一次，不逐字段重复打断。例外：用户名/密码等需在切换前校验（HIG 原文）。
- **错误定位与可见性**：错误以文本指出**具体字段与原因**（回指 §无障碍基线 `3.3.1` / `3.3.3`），聚焦错误字段或把错误摘要置顶；**不只靠颜色**（回指 `1.4.1`）。
- **不重复输入**：多步骤表单里已填数据跨步骤复用，不重新要求（回指 `3.3.7`）；认证流程不依赖认知测试（回指 `3.3.8`）。
- **高风险提交前确认**：涉及法律 / 金融 / 数据删除的提交，提交前给「摘要 +（撤销 / 可查错 / 确认 三选一）」；本仓对法律/金融/删除类**加严为「至少可查 +（可逆或确认）」**（★ 本仓加严，循 `:313` 先例；官方 3.3.4 为三选一）。
- **标签与说明**：每个输入有可见标签或说明（回指 `3.3.2`）；**占位符不是标签**；必填用文字或明确符号，不只靠星号颜色。
- **非闸门 + 判定落点**：本节不进 §交付闸门（条目数固定），判定落 `frontend-design` §Web 质量自检 2 行；App 侧判定落 `app-design` 三分支表单自检各 1 行（Flutter `FocusNode` / SwiftUI `@FocusState` / Compose `focusRequester`）。

> **分工**：§感知时延阈值 是展示义务表，本节是校验时机；§边界状态管「空数据 vs 无权限 vs 断网」四态，本节管「字段级错误」，错误态 ≠ 空态；§状态机 Error = 数据视图级错误（唯一出处，本节不重述「保留已输入内容」）；§贴图规范管输入组件显式宽高 / `autocomplete`；§交互规范 · 生成式 AI 基线管 AI 生成表单内容的可编辑/撤销。4.1.3 之「不移动焦点」限**异步状态消息**语境，提交失败后的焦点引导属用户触发流。

## 自适应布局（跨端）

> 依据：Android adaptive 文档（`developer.android.com/develop/ui/compose/layouts/adaptive`，2026-10-26 直读）与 MDN 容器查询（`container-type` 为 Baseline 广泛可用，2026-10-26 核）。只写跨端取舍与自检判据；断点数值按 Android 官方表摘录（以官方为准），平台 API 与实现教程归各自 owner。

- **尺寸驱动，不认设备**：布局分支只看**可用宽度/尺寸类**——Android 用窗口尺寸类（宽度 compact < 600dp / medium 600–839 / expanded 840–1199 / large 1200–1599 / extra-large ≥ 1600；高度 compact < 480dp），iOS 用 size class 与窗口尺寸，Web 用**内容断点 + 组件级容器查询**（`container-type` + `@container`）。**禁止**按机型、UA、`screen.width` 分支；屏幕方向与折叠姿态见 §形态与共存。
- **先选模式再画**：画之前先定布局模式——list-detail（主从）/ supporting pane（主 + 辅）/ feed（单列流）；导航形态随宽度切换（bottom bar → rail → drawer）。**不手写尺寸分支与返回动画**（M3 Nav3 已覆盖，见 §平台设计语言硬规则 · M3）；宽度到 medium 但高度 compact（如横屏手机）时不做双栏。
- **多窗口不破**：窗口宽度是**范围不是承诺**（分屏、自由窗口、外接显示器都可能比预期窄）；窄窗与 50% 分屏下主操作不被遮挡、无横向溢出；量测用**窗口/容器宽度**，不是屏幕宽。
- **密度而非放大**：大屏**加列/加信息**，不把手机稿等比放大；**动态字号放大时不得靠加大间距补偿**（一屏两行是最常见坏味道）；除显式声明的横向画廊外，交付说明须写出 `overflow-x` 的用途（实现层断点 token 见 `product-prototype-generation`：原型层（其模板与 golden）viewport 断点可接受；正式 Web 交付的组件级按本节用容器查询，不在此重抄）。
- **非闸门硬禁令**：本节的「禁止」项不进 §交付闸门（闸门条目数固定，改计数须同轮改断言与 selftest），判定走 §跨端系统自检清单。

**天花板**：断点是否贴合具体产品内容、分屏下是否真的「不遮挡」需真机实测；本节只给判据，不给实现教程。

> 依据：Android insets / edge-to-edge 与 FoldingFeature 文档（`developer.android.com`，2026-10-26 直读）、Apple `keyboardLayoutGuide`（WWDC21-10259 / WWDC23-10281 正文，2026-10-26 核）、MDN `env()` / `@media hover` 基线（2026-10-26 核）。只写跨端判据；平台 API 与实现教程归各平台 owner。

**与 §自适应布局 的分工**：宽度决定「用哪种布局模式」归 §自适应布局；形态事件与输入设备决定「重建后保什么、谁让位」归本节。冲突时先按 §自适应布局 选模式，再按本节保状态与避让。

- **形态变化不是换页**：旋转、分屏拖动、窗口缩放、折叠开合后，滚动位置、已填输入、选中项、播放进度、导航栈保持；**禁止**因形态事件回顶、重放首屏动画、丢焦点（后台恢复的「不重放进入动画」见 §交互规范）。
- **键盘与安全区是布局的一部分**：软键盘/候选栏弹出时输入框可滚到可见、底部固定操作让位；收起后不留空白；底栏不与手势条重叠；**安全区取系统 inset，不硬编码高度**。Web 的 `safe-area-inset-*` 属 Baseline（2026-10-26 核 MDN），虚拟键盘几何属 Limited availability（同日核），**只能渐进增强**。
- **折叠看姿态，不看角度**：半开态按铰链方向分区——水平铰链=展示区/操作区，垂直铰链=左右两栏；铰链/折痕区域不放关键内容与可点元素；**禁止**按铰链角度做布局或动画分支（平台不暴露角度）。
- **共存不抢**：分屏/多窗口失焦时不弹模态、不自动播放音视频、不抢输入焦点；后台恢复口径见 §交互规范 · 边界状态。
- **输入能力分档**：hover 增强只在可悬停的精确指针下生效，触屏必须有等价可见反馈，**hover 不作唯一反馈**；笔的悬停/压感不承载唯一信息。（键盘可达与焦点可见不在本节立判据，按 `accessibility/platforms/*` 判定。）
- **输入法（IME）组合态不抢跑**：组合期间回车只确认候选，**不触发提交/搜索/校验**；组合结束后再取值；候选栏高度变化按上一条让位。
- **非闸门硬禁令**：本节「禁止」项不进 §交付闸门（条目数固定），判定走 §跨端系统自检清单。

**天花板**：键盘/候选栏实际高度、折叠真机姿态、笔的实际精度、iPadOS 指针悬停求值、多窗口同数据编辑语义需真机/人工裁定；本节只给判据。

## 国际化与 RTL（跨端）

> 依据：MDN `:dir()`（Baseline Widely available，since 2023-12）、`margin-inline-start` 与 `<bdi>`（Widely available，since 2020-01）、`Intl.PluralRules`（Widely available）均 2026-10-26 直读；Android `android:supportsRtl`（manifest 文档，同日核）、Apple `UIView.semanticContentAttribute`（文档页同日确证）、Flutter `Directionality` / `EdgeInsetsDirectional`（`api.flutter.dev`，同日核）。只写跨端判据；平台 API 与实现教程归各平台 owner。

**与相邻章的分工**：宽度决定布局模式归 §自适应布局；形态事件保状态归 §形态与共存；**语言与文字方向决定镜像、断行与格式**归本节（「文字方向」≠「屏幕方向」）；单位 / 字阶 / 字距 / 行高默认值（拉丁口径）归 §字体规范，随语言的调整归本节。

- **文案是数据，不是设计常量**：不按字符数裁切、不写死按钮 / 标签宽度；容器给 `min-width` 并允许换行；截断不得丢失控件语义完整名称（判定回指 `accessibility/platforms/*`）；译文比中文长是常态，须为膨胀留余量（比例属判断，见天花板）。
- **镜像用逻辑属性，不写死 left / right**：Web `margin-inline-*` / `inset-inline-*` / `text-align: start`；iOS 前缘 / 后缘语义；Android `start` / `end`；Flutter `EdgeInsetsDirectional`。**不镜像**内容自带物理或固有方向的元素（媒体进度、时间轴等）——方向切换时保持原方向。
- **文字方向由系统或内容决定**：Web `dir` + `lang`（`:dir()` 可作选择器增强）；iOS `semanticContentAttribute`；Android 布局方向属性；Flutter `Directionality`。**禁止**用 JS 反转或 `transform: scaleX(-1)` 伪造 RTL。
- **排版随语言，不随设计稿**：`lang` 决定断行、标点与字体回退；CJK 与拉丁混排的字距与行高随语言调整；行高按文字高度类别（见 §平台设计语言硬规则 · M3）。
- **格式化与双向文本走系统能力**：数字 / 日期 / 货币 / 复数用本地化 API（`Intl` / `DateFormatter` / ICU），不手写拼接与单复数规则；双向混排用方向隔离标记（`<bdi>` / `dir="auto"`），避免数字与标点跳位。
- **非闸门硬禁令**：本节「禁止」项不进 §交付闸门（条目数固定），判定走 §跨端系统自检清单。

**天花板**：文案膨胀的实际比例、阿拉伯 / 希伯来 / 天城文的字体回退与混排字距、RTL 真机首选语言抽查需人工裁定；本节只给判据。

## 兼容基线（跨端）

**与相邻章的分工**：本章定「哪些能力可用、不支持怎么退」；宽度分流归 §自适应布局，键盘与安全区归 §形态与共存。

- **口径**：默认可用的上限是 MDN Baseline `widely available`（在全部 Baseline 浏览器中稳定支持 ≥2.5 年，2026-10 核读）；`newly available` 只能作增强并附降级；`limited availability` 不得作为唯一路径。
- **三层判定**：① 基线内 → 直接用；② 新特性 → 特性检测或 `@supports` 内使用 + 降级；③ 不支持时 → 内容可读、操作可完成。
- **Web 高风险清单**（每项必须写退路）：`dvh` / `svh` 定高全屏（不用裸 `100vh`）；输入字号 ≥16px（防 iOS 聚焦缩放）；`backdrop-filter` 需 `-webkit-` 前缀且不得作唯一层级手段；`env(safe-area-inset-*)` 需配 `viewport-fit=cover`；`-webkit-tap-highlight-color`；`overscroll-behavior`；`scrollbar-gutter`；sticky 在滚动容器内失效；`text-box-trim` 属 Baseline 2026 新增（2026-10 核读），只能增强、用 padding 兜底。
- **App 下限声明**：iOS 17+ / Android 10+；低于下限只保可用不保视觉；平台 API 分支用 `#available` / `Build.VERSION`，不用型号判断。
- **验证矩阵必须贴表**，未测项写 N/A 并给理由：Web 320 / 360 / 390 / 430 / 768 / 1024 / 1440 × Safari(iOS) / Chrome(Android) / 桌面三引擎；App 360dp / iPhone SE / 标准 / 大屏 / 平板 × 系统字号 130% / 200% × 深色 / 浅色。

**天花板**：真实设备碎片化无法穷举；矩阵外的机型只作「已知风险」登记，不据此判缺陷。

## 平台设计语言硬规则

### Apple — Liquid Glass（iOS 26+）
- `Regular` / `Clear` 两种变体 **绝不可混用**。
- **只用于导航层**，禁止放在内容层，**禁止玻璃嵌套玻璃**（**内容层瞬态例外**：滑块 / 开关等瞬态交互控件在用户操作瞬间可呈玻璃外观以强调可交互性；非常驻、不延伸为其他内容层元素——HIG 原文限此类控件的激活瞬间，「不延伸」为本仓加严；2026-10-26 直读）。
- **文字永远在实色层上，绝不直接压玻璃**（可访问性硬规则）。
- `Clear` 三条件**全满足**才用：①位于媒体丰富内容之上 ②内容层不受 dimming 层影响 ③上方内容 bold and bright。
- Tint 只给主要操作，**全部元素都 tint = 混乱**。
- Scroll Edge Effects 取代硬分隔线；Action Sheet 从相关操作处弹出。
- Scroll edge effect **只在「滚动内容位于浮动控件之后」时用**（不是装饰）：每视图一个，优先 `automatic` 样式（`soft` 须实测控件可读性），**不手绘渐变遮罩/压条**（本仓禁令；HIG 允许在自定义 bar 上手动施加的仍是系统 effect 本身）。
- 自定义 toolbar 移除背景色，靠布局与分组表达层级。
- Reduced Transparency / Increased Contrast / Reduced Motion **自动生效**，不得绕过。
- 增量指引（2026 HIG）：Menus 图标仅辅助文字；Sidebars 用 tint 图标 + adaptable 样式；App icons 按 Liquid Glass 分层设计（可用 Icon Composer 单设计出 iPhone/iPad/Mac/Apple Watch；随 Xcode 提供，亦可从 Apple Developer 网站获取，2026-10 正文核读）。
- App icons 外观：default / dark / clear / tinted 四种均保留**同一核心特征**（替代图标也要各自有变体）；高光 / 层间投影 / 模糊由系统施加，**不需要手绘**（刻意加须用 Icon Composer 实测）；前景层用矢量（SVG/PDF）且**不预置遮罩**（形状交系统 mask），主体居中防裁切；不使用 Apple 硬件复制品。
- 搜索走系统 search 能力（Search tab / `.searchable`），**不自绘搜索框**；入口三选（tab 栏 / 工具栏 / 内联字段），底部有空间时优先底部，**底部内容为主或无底部工具栏时置顶**；tab 两风格：`standard` 先给建议与分类（供发现）、`button` 直接聚焦出键盘（求快）。
- SF Symbols 必须显式选渲染模式（monochrome / hierarchical / palette / multicolor，可选 gradient），同界面只用 1 种；variable color 只表达状态或强度，状态变化仍走填充度 + 双通道。
- 触觉只用于结果确认 / 警告 / 选择三类，不与装饰动画绑定；用系统 API（`SensoryFeedback` / `HapticFeedback`），不自造震动参数。
- Siri / Spotlight / Shortcuts 的结果用 snippet：`confirmation` 双按钮（次要 Cancel + 主按钮，**须给具体动词**；系统默认 Continue 不满足本仓要求）、`result` 单 Done；自定义视图 ≤400pt、内容精简，更长内容深链回 App。
- Siri 回话须**可独立朗读**（不依赖屏幕元素补齐信息）、不重复 App 名、错误说具体原因；不冒充 Siri、不使用「Hey Siri」等保留短语。

- **全屏背景要延伸到系统栏之下**：满屏背景图铺到 sidebar / toolbar / tab bar 之下（不留色块裙边）。若侧栏 / 检查器会压住图像关键部分，用系统 **background extension effect**（SwiftUI `View.backgroundExtensionEffect()` / UIKit `UIBackgroundExtensionView`）——由系统翻转 + 模糊镜像到相邻组件下方；**不自绘镜像 / 模糊 / 渐变遮罩**。本条「满屏背景」场景与 Scroll edge effect 的「滚动内容位于浮动控件之后」不同，二者不可互换（后者的手绘禁令与本条同源）。（HIG Layout 正文，2026-10-26 直读）

#### iPhone Duo（折叠 iPhone；HIG「Designing for iPhone Duo」页 2026-09-09 上线，本仓核读 2026-10-26）

> 折叠**通用**判据（形态重建保状态、铰链/折痕区避让、看姿态不看角度）见 §形态与共存；机型 / UA 分支禁令见 §自适应布局。本块只写 Duo 特有差异。

- **两种尺寸类别 = 屏幕态，不是 App 态**：外屏 compact（相对直板 iPhone 更宽更矮，系统把 tab bar / toolbar / 导航控件竖排到侧边以保留内容高度）；内屏 regular（常规横向栏）。
- **内屏可被系统 Split View 并排双 App**：按**当前可用宽度重新落档**，不得把「内屏＝双栏」写死；半宽下按 §自适应布局 的档位判据降级（原型侧档位阈值与设备数值 owner 见 `product-prototype-generation`）。
- **reserved regions 是条件区域，不是固定中间槽**：外前摄常驻（可扩进 Dynamic Island）、内前摄仅相机激活时占用、折痕区随姿态存在。系统组件（alert / sheet / context menu / split view）自动让位；自定义锚定控件用 `ReservedRegion`（SwiftUI / UIKit；iOS 27.1+，以 SDK 为准——availability 已核 2026-10-26）避让。
- **本条禁止的是 App 实现里写死前摄 / 折痕几何**；原型渲染所需的估计折痕宽度与 cutout 属 `product-prototype-generation/constants.js`（【估计】级数据），不视为违规。
- **跨折痕网格用偶数列** + 足够外层边距，让每格完整落在单侧（HIG：格线跨折痕时优先偶数列，使内容在两侧分得整齐）。
- 跨折痕的**连续内容**（文章 / 列表 / 信息流）保持连续滚动，不跳区。
- 内外屏**比例近似**（官方称同宽高比），故布局**不以比例分支**；几何数值与推导 owner 在 `constants.js`。
- 分栏用系统容器：`NavigationSplitView` / `UISplitViewController`；需要姿态感知移位时用 arrangement view（split / overlay），不机械替换所有 `HStack/VStack/ZStack`。
> **归因**：块内除下列两处外均为 HIG「Designing for iPhone Duo」直述——① 「跨折痕连续内容保持连续滚动、不跳区」为本仓引申（HIG 最近似句「Avoid extreme layout changes…favor small adjustments over rearranging」针对尺寸类别切换时的控件排布，未覆盖滚动连续性；本仓据此扩到连续内容）；② 「内外屏比例近似」出自 Apple Newsroom 2026-09-09（「Both displays share the same aspect ratio」），HIG Duo 页无此句。

### Material 3 Expressive（Android）
- 形状库 + 形状变形可用，但**官方警告要克制**，否则混乱。
- 弹簧物理动效取代标准 easing。
- 大按钮 + 次要色强调（研究：关键元素识别快 4 倍，老年用户追平年轻用户）。
- 可变字体轴可做动态字重/字宽。
- Expressive layout system：新 layout scaffold + **8dp 基准 spacing token**（可编程适配设备/密度，与 §间距 4/8 基准兼容不冲突）。
- Android 转向 Compose-first：Material Views 1.14 为**最后一个 stable 发布**（官方 "all in on Compose"），此后仅维护；Material Compose 1.5.0 预计 2026 H2 发布并转 stable（截至 2026-10-26：stable 1.4.0 / beta 1.5.0-beta02），转 stable 后 Expressive 实验 API 才可作默认位，此前仍以 stable API 为准。
- Type scale 支持按语言文字高度类别自适应行高（与 App「字号跟随系统」方向一致）。
- 列表两形态：standard / segmented；segmented 由容器自动管理 adaptive corner shapes 与选中态配色（点击 / 切换 / 选中即时变换容器），**不需手绘选中背景**。
- Search 可与 App bar 一体：navigation / action 槽位在搜索容器之外；`contained` 展开后仍保留折叠形态（持久容器），`expanded dock search bar` 可平滑过渡。
- Menu 分组用 `MenuDefaults.GroupShape`（自动圆角容器）+ gaps 呼吸间距，**不手绘分组背景**。
- 自适应导航（Nav3）：按 backstack + 屏幕尺寸自动单栏 / 双栏（list-detail），并自带 Predictive Back 预览；采用 Nav3 + Material adaptive 时**不手写尺寸分支与返回动画**。
- 状态化样式可用 Styles API（Compose `@Experimental`；foundation 1.12+ / BOM 2026.04.01 起）：替代样式参数（padding / 颜色），**不替代 modifiers**；实验期内不得挤掉 stable API 的默认位。
- Styles 口径以 foundation 1.12 stable 为准；Material 组件原生 style 参数官方仅称「future releases」（与 Material Compose 1.5.0 同期推进，未点名版本；截至 2026-10-26 仍未点名），实验期 API 形状仍在变。
- Predictive Back：Android 16+ 默认开启，返回手势必须有预览；13–15 需 `android:enableOnBackInvokedCallback`，交付注明目标版本。
- 返回事件拦截走系统回调（Compose `BackHandler` / `OnBackInvokedCallback`），不为埋点或业务逻辑消费返回事件，不自绘返回按钮。
- Dynamic Color 是可选的系统取色层，**不是品牌色**；关掉动态取色后品牌识别必须仍成立。

## 无障碍基线（WCAG 2.2 AA）

对比度与触达尺寸见上文。以下高频条款进自检（**等级列标明该 SC 的官方等级**，仅 `A` / `AA` / `AAA`，表内按 A → AA → AAA 排列；本仓把 2.3.3 从 AAA 升为强制项）。条款号对照以 W3C 官方为准：`1.4.1` = Use of Color（A），`1.1.1` = Non-text Content（A），`2.1.1` = Keyboard（A），`4.1.2` = Name, Role, Value（A），`1.4.3` = Contrast（AA，已由 §对比度 覆盖），`4.1.3` = Status Messages（AA），`2.4.7` = Focus Visible（AA），`2.4.13` = Focus Appearance（AAA，未登记，本仓仅在焦点对比度上作加严参考）。

| 编号 | 等级 | 要求 | 踩坑场景 |
|---|---|---|---|
| 3.2.6 | A | 帮助入口跨页相对顺序一致 | 同一站点「帮助/联系」每页位置漂移 |
| 3.3.7 | A | 不重复输入 | 已填过的地址在后续步骤再次要求 |
| 3.3.1 | A | 错误识别 | 错误必须以文字明确指出具体字段与原因，不能仅靠颜色/位置/图标 |
| 3.3.2 | A | 标签或说明 | 每个输入有可见标签或说明；占位符不是标签 |
| 1.4.1 | A | 不能仅用颜色传达信息 | 仅红色表示错误，须补图标/文字 |
| 1.1.1 | A | 非文本内容有替代 | 有意义的图片/图标无替代文本；装饰图被读屏逐张朗读 |

## 额度与观察期

`qwen3.8-max` 单价为 `qwen3.7-plus` 的 **5x（input）/ 3.75x（output）**。

## 两遍工作法（先计划后写码）
### 第一遍：设计计划（先脑内完成，交付时按模板精简展示）
- **颜色**：4-6 个命名 Token 体系（Web 用 Hex；App 用平台主题系统的 Color/ColorScheme）。
- **字体**：2+ 角色（克制使用的个性 Display + 互补 Body + 可选 Utility）。
- **布局与骨架**：容器最大宽 + gutter + 共轴方向 + 块内/块间节奏；一句话概念 + 线框比选（Web 用 ASCII；App 用 Widget/View 结构描述）；页面清单 × 继承哪个 shell；碎片页（detail / modal / 空态）写明归属。
- **组件矩阵**：本次控件 × `control-size` × 变体 × 状态；同类语义的固定写法。
- **衔接与兼容**：层级模型（push / modal / replace / reveal）+ 转场与降级 + 待测机型/浏览器矩阵。
- **签名**：全页/全屏只一个会被记住的元素，且能体现 Brief。
- **校准俗套**：各平台俗套清单见本节 §俗套校准表（唯一权威源；各 skill 只做指针引用），Brief 明示要才用，否则换自由轴。

### 自检再开工
- 换一道相似题自问：是否会得出同样方案？若会，说明是通用默认，重改该部分并说清改了什么、为什么。

### 第二遍：写码
- 严格按修订后计划执行，所有颜色字型决策皆有出处。
- 收尾自检如照镜子：删掉一个多余装饰（Chanel 法则）。

## 通用自检清单（交付前必过）
- [ ] 签名唯一：全页/全屏只有一个记忆点，其余安静
- [ ] 去俗套：颜色/字体/布局任一轴与平台俗套不同，或 Brief 明示要求
- [ ] 字型可辨：字阶/间距有意，含字体加载/注册策略
- [ ] 结构诚实：编号/分割线编码真实信息，无装饰性 01/02/03
- [ ] 动效有因：每个动画能说出服务主题的理由，系统减弱动效设置下（Web `prefers-reduced-motion` / iOS Reduce Motion / Android 移除动画）仍可用

## 跨端系统自检清单（与上表合并判定）
- [ ] Token 无硬编码：组件层无字面色值/像素值
- [ ] Token 分层：全局层 + 产品层，覆盖有说明
- [ ] 对比度：正文 4.5:1、大字/图标 3:1 全达标
- [ ] 暗色：走语义映射表，无「反转」式实现
- [ ] 图标：权限合规（SF Symbols 未跨平台）、同语义唯一、无独立承载语义
- [ ] 贴图：同屏未混用来源、同一角色未混用、色调处理统一、**AI 图留痕已落盘 manifest**
- [ ] 交互：四态齐备、无裸转圈、无「暂无数据」误用
- [ ] 边界：网络/低电量/后台恢复/中断恢复均有对策
- [ ] AI：涉及生成式 AI 的界面已过 §交互规范·生成式 AI 交互基线（标识 / 可编辑·撤销·重试 / 不可逆先确认 / 不确定标注 / 等待 / 多版本 / 隐私）；无 AI 功能则跳过
- [ ] 触达：取 iOS 44pt / Android 7-10mm / WCAG 24px 最严者
- [ ] 自适应：宽度驱动（尺寸类 / 容器查询），无机型、UA、屏宽分支；窄窗与分屏下主操作不被遮挡、无横向溢出
- [ ] 自适应：布局模式先定（list-detail / supporting pane / feed）、导航随宽度切换；大屏加列不加字号、字号放大不靠间距补偿、`overflow-x` 用途已写明；medium 宽 + compact 高不双栏；尺寸分支与返回动画交 Nav3、不手写
- [ ] 形态切换（旋转/分屏/折叠/缩放）：滚动位置、已填输入、选中项、播放进度、导航栈不丢且不丢焦点，不因形态事件重放首屏动画；折叠按姿态不按角度，铰链/折痕区无关键内容
- [ ] 键盘与安全区：聚焦输入可滚到可见、收起无残留空白；安全区取系统 inset、底栏不压手势条；输入法组合态回车不提交
- [ ] 共存（分屏/失焦）：不弹模态、不自动播放、不抢焦点
- [ ] 输入能力：hover 仅在可悬停设备生效且不承载唯一反馈；触屏有等价反馈
- [ ] 文案：无按字符数裁切、无写死宽度，截断不丢语义，译文膨胀留量
- [ ] 镜像：逻辑属性（`margin-inline-*` 等），固有方向元素（媒体进度 / 时间轴）不镜像
- [ ] 方向与排版：`dir` + `lang` 或平台方向 API 声明，无 JS 反转或 `scaleX(-1)` 伪造；断行 / 标点 / 字距随语言
- [ ] 本地化格式：数字 / 日期 / 货币 / 复数走本地化 API，双向文本已隔离
- [ ] 动效（含降级态）：不阻塞输入与首屏；滚动驱动有 `@supports` 降级、无动画也可读，长列表禁用、不替代加载态
- [ ] 无障碍：WCAG 2.2 AA 高频条款全过
- [ ] 对齐：同容器单对齐轴、左右贴 gutter、跨字号走文本基线、数值列右对齐；无逐块微调
- [ ] 组件唯一：同类控件只有一处定义；按钮高度 / 圆角 / 输入框边框各只有一种；触控命中区 ≥ 取最严值
- [ ] 跨页：header、导航、页脚、主 CTA、帮助入口跨页同位同尺寸；抽 2 页实测五项一致
- [ ] 衔接：层级模型与转场方向一致；返回恢复滚动/筛选/输入；无动画时完整可用；减弱动效降为瞬时
- [ ] 兼容：能力全部落在 Baseline widely，或带 `@supports` 降级；验证矩阵已贴表，未测项写明 N/A 与理由
- [ ] 选轴：偏离默认项已写出理由
